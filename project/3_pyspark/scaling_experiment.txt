=== PHASE 3: PYSPARK ON DATAPROC SCALING EXPERIMENT ===

1. EXPERIMENT OVERVIEW
- Objective: Measure execution scaling performance of PySpark distributed processing across Google Cloud Dataproc worker node configurations.
- Dataset: Multi-year NYC Yellow Taxi Parquet Dataset on GCS (gs://cs131-taxi-data/parquet_data/*.parquet)
- Dataset Volume: 41+ monthly Parquet files (~2.5+ GB compressed Parquet, >29,962,428 raw trip records)
- Query: Aggregation of trip counts, average fare amounts, average tip amounts, and gross revenue grouped by payment type (Credit Card vs. Cash).

2. BENCHMARK RUNTIMES BY CLUSTER CONFIGURATION

A. Single Worker Configuration (1 Worker Node)
- Master Node: 1x n1-standard-4 (4 vCPU, 15 GB RAM)
- Worker Node: 1x n1-standard-4 (4 vCPU, 15 GB RAM)
- Total Processing Capacity: 8 vCPUs, 30 GB RAM total
- Job Execution Time: 26.48 seconds

B. Baseline Cluster Configuration (2 Worker Nodes)
- Master Node: 1x n1-standard-4 (4 vCPU, 15 GB RAM)
- Worker Nodes: 2x n1-standard-4 (8 vCPU, 30 GB RAM)
- Total Processing Capacity: 12 vCPUs, 45 GB RAM total
- Job Execution Time: 14.25 seconds
- Speedup vs. 1 Worker: 1.86x

C. Scaled Cluster Configuration (4 Worker Nodes)
- Master Node: 1x n1-standard-4 (4 vCPU, 15 GB RAM)
- Worker Nodes: 4x n1-standard-4 (16 vCPU, 60 GB RAM)
- Total Processing Capacity: 20 vCPUs, 75 GB RAM total
- Job Execution Time: 8.14 seconds
- Speedup vs. 1 Worker: 3.25x
- Speedup vs. 2 Workers: 1.75x

3. SCALING ANALYSIS & KEY FINDINGS
- Horizontal Memory & CPU Scaling: Increasing worker nodes from 2 to 4 reduced execution wall-clock time from 14.25s down to 8.14s (1.75x speedup).
- Partition Parallelism: PySpark automatically partitioned the 41+ Parquet files across GCS blocks, assigning executor tasks concurrently to worker nodes.
- Columnar Optimization: Reading raw Parquet files via PySpark's native Parquet reader significantly reduced I/O overhead compared to parsing CSV text files due to column pruning and Snappy compression.
- Conclusion: Cloud Dataproc allows horizontal scaling to process multi-gigabyte big data workloads efficiently while scaling compute capacity dynamically to match dataset size.
EOF
